# Core conformance

The frozen profile is **0.1.0-core**, defined by [the core contract](../specification/core/core.md).
Conformance covers a complete project snapshot. Reader/editor and mutation support require
additional behavioral evidence.

## Criteria and coverage

| ID | Required result | Package evidence | Tool acceptance |
| --- | --- | --- | --- |
| C01 | Exact root profile and scoped catalog. | Profile fixtures and scope. | Recognize the declared version. |
| C02 | Unique-key YAML, required metadata and namespaced extensions. | Envelope/schema fixtures. | Preserve extension fields. |
| C03 | Document title and preservation contract. | Title, hard-break, list and code fixtures. | OP07, OP09: byte round trip and localized edit. |
| C04 | Explicit versions role and diagnostics on conflict. | Malformed, duplicate and unmarked table fixtures. | OP08: preserve conflicting blocks. |
| C05 | Legal tree, descriptors, width, depth and index. | Tree fixtures, including 255/256 boundary. | OP01: concurrent allocation. |
| C06 | Unique GUIDs and valid entity/asset links. | Duplicate, dangling, path, fragment, image and code fixtures. | Move preserves identity. |
| C07 | Catalog, forward authority, cardinality and uniqueness. | Relation fixtures, including symmetric duplication. | Enforce on mutation. |
| C08 | Exact sharded derived reverse index. | Complete example; missing/stale/wrong/duplicate-key records. | OP02, OP05: recovery/rebuild. |
| C09 | Atomic visibility, conflict, deletion and explicit repair. | Nine black-box acceptance scenarios supplied. | Run OP01–OP06 against a runtime. |
| C10 | Versioned schemas and release package. | Schema checks, publication links and governance. | Declare tested capabilities. |

## Run the package checks

Python 3.10 or newer with venv and pip is required. From the repository root:

```sh
python3 -m venv .venv-core
.venv-core/bin/python -m pip install -r conformance/requirements.txt
.venv-core/bin/python conformance/check_release.py
.venv-core/bin/python conformance/validate.py examples/core-project
```

On Debian without ensurepip, install the matching python3-venv package or use an existing
Python distribution with venv support. Installation needs the package index; checks run
offline and resolve schema IDs locally.

The release command checks schemas, fixture expectations, diagnostic consistency, the
example/read-only behavior, scenario completeness and local publication links. CI runs it too.

The snapshot validator prints JSON: exit **0** valid, **1** conformance errors, **2** I/O or
usage failure. It never repairs input. It tokenizes Markdown links so code examples are not
graph edges. A passing static report is not evidence of a production serializer, watcher or
atomic mutation implementation. Full Markdown engine compliance also belongs to the
candidate implementation's suite.

## Fixtures and limits

- [cases.json](fixtures/cases.json): start from the example and apply explicit replacements,
  additions/removals and optional empty folders. Expected validity and diagnostic codes are
  independent expectations; expected indexes are authored, not generated by the validator.
- [operations.json](fixtures/operations.json): black-box input/action/outcome scenarios.
  Package checks verify their completeness, **not runtime outcomes**. A candidate tool must
  record its version, scenario ID, actual observations and result. No runtime is certified here.
- [Core project](../examples/core-project/README.md): four entities, a dependency, a body link,
  a versions table, an asset and checked-in reference-index fixtures.

New requirements must add positive/negative or behavioral cases in the same change.
